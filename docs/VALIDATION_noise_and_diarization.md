# 验证报告：噪声与说话人分离

> 目的：在改动之前先搞清楚**现有工具到底哪里达标、哪里不达标**。
> 所有数字都是在本机实测的，样本和命令都写在下面，可以复现。

---

## 结论速览

| 问题 | 判定 | 依据 |
|---|---|---|
| 背景噪声会不会拖累识别？ | **不会** | 噪声加到 0 dB SNR（和人声一样响），仍保留 **93%** 内容、**0 幻觉** |
| 加降噪有没有用？ | **没有，反而更差** | 降噪后保留率降到 **90%**；`dpdfnet2` 还会丢掉 9% 的词 |
| 说话人分离能不能用？ | **自动模式不可靠，指定人数可靠** | 双人播客自动给出 **6 人**（真实 2 人）；`--num-speakers 2` 精确 |
| 要不要做人声/伴奏分离？ | **暂时不做** | 背景噪声不影响识别；"唱歌/欢呼变成文字"是另一个问题，需单独验证 |

**方向**：不要加降噪；把力气花在说话人分离的聚类上（已修一部分）。

## 一、测试样本

用 yt-dlp 从 YouTube 取前 180 秒，转成 16 kHz 单声道 WAV：

| 样本 | 来源 | 特点 | 噪声画像 |
|---|---|---|---|
| `sample_noisy_conversation` | `youtube.com/watch?v=6PJnEdbq8qc`（真实语速对话练习） | 两人对话、自然语速、有环境声 | 噪声底 −48.5 dB，动态范围 31.3 dB，静音 17% |
| `sample_podcast2` | `youtube.com/watch?v=35n0J7InCyw`（双人播客） | **真实 2 人**、近距离收音 | 噪声底 −62.1 dB，动态范围 30.6 dB，静音 22% |

```powershell
python -m yt_dlp "https://www.youtube.com/watch?v=35n0J7InCyw" --proxy http://127.0.0.1:7890 `
    --format "bestaudio/best" -o "bench\sample_podcast2.%(ext)s"
ffmpeg -y -ss 20 -t 180 -i bench\sample_podcast2.webm -vn -ac 1 -ar 16000 -c:a pcm_s16le bench\sample_podcast2.wav
```

## 三、噪声到底有没有影响：受控注入实验

真实样本的"吵"不可控，所以用**已知信噪比混合**来测：把干净语音和粉红噪声按指定 SNR 叠加，
再和干净版对比词级保留率。

去掉唱歌/欢呼这类"有词噪声"，先用无词噪声测**识别本身**的抗噪能力。

| 条件 | 词数 | 保留率 | 幻觉 |
|---|---|---|---|
| 干净（参照） | 448 | 100% | 0 |
| 粉红噪声 SNR 20 dB | 451 | **95%** | 0 |
| 粉红噪声 SNR 10 dB | 443 | **94%** | 0 |
| 粉红噪声 SNR 5 dB | 446 | **94%** | 0 |
| **粉红噪声 SNR 0 dB** | 436 | **93%** | 0 |

**噪声和人声一样响（0 dB SNR）时，识别仍保留 93% 内容，且没有任何幻觉。**

原因：faster-whisper 默认开了 VAD（`vad_filter=True`），静音和非语音段本来就先被掐掉；
再叠加 Whisper 本身是在大量噪声数据上训出来的，对加性噪声非常鲁棒。

## 四、降噪有没有用：A/B 对比

两个 sherpa-onnx 降噪模型，同一段音频：

### 4.1 在真实样本上

| 配置 | 字数 | 英文词 | 幻觉 | 动态范围 |
|---|---|---|---|---|
| 原始 | 2393 | **534** | 0 | 31.3 dB |
| `gtcrn_simple`（0.5 MB） | 2351 | **520**（−2.6%） | 0 | 59.1 dB |
| `dpdfnet2`（9.8 MB） | 2171 | **485**（−9.2%） | 0 | 66.3 dB |

### 4.2 在受控噪声上（每档都跑"噪声直转" vs "降噪后转"）

| SNR | 噪声直转保留率 | 降噪后保留率 |
|---|---|---|
| 20 dB | 95% | 93% ↓ |
| 10 dB | 94% | 93% ↓ |
| 5 dB | 94% | 93% ↓ |
| 0 dB | 93% | **90%** ↓ |

**结论：降噪把动态范围从 31 dB 拉到 59~66 dB（听感上确实更干净），但识别保留率每一档都略降。**

原因是降噪模型会连带削掉一部分弱辅音和词尾 —— 对人耳是"更清楚"，
对声学模型是"少了信息"。

**所以本项目不集成降噪。** 想做也应该是"给需要的人一个开关"，而不是默认开。

## 五、说话人分离：真实短板在这里

### 5.1 自动判断人数不可靠

双人播客（真实 2 人），阈值扫描：

| 配置 | 检测到人数 | 判定 |
|---|---|---|
| 阈值 0.90（原默认） | **6** | ✗ 过分割 3 倍 |
| 阈值 0.95 | 5 | ✗ |
| 阈值 0.99 | 4 | ✗ |
| **`--num-speakers 2`** | **2** | ✅ |
| `--num-speakers 3` | 3 | ✅（按指定走） |

**固定阈值救不了这个问题** —— 相似度的绝对尺度在不同音频上不一致。

### 5.2 根因：长尾小簇不是人

同一个样本在阈值 0.90 下的簇时长占比：

```
S1 73.6%   S2 19.5%   S3 3.7%   S4 2.6%   S5 0.4%   S6 0.3%
```

后四个加起来不到 7%。它们是噪声、串音、咳嗽、椅子响聚出来的假人，
不是"两个说话人之一"。所以调阈值没用 —— 这些簇的嵌入确实彼此不像，
它们本来就不是同一个人说话。

### 5.3 修法：按占比合并碎簇

在 `diarize.py` 里加 `prune_rare_speakers()`：把时长占比 <5% 的簇合并到时间上最近的说话人
（合并而不是丢弃，否则那几秒的字幕会没有说话人标签，输出看起来像坏了）。

效果：

| 样本 | 修复前 | 修复后 | 真实 |
|---|---|---|---|
| podcast2 | 6 人 | **2 人** | 2 ✅ |
| noisy_conversation | 3 人 | 3 人 | 2~3（保留了 8.6% 的那簇，保守处理）|

## 六、仍然存在的问题（诚实记录）

### 6.1 快速对话轮次会并簇

podcast2 前 24 秒是明显的两人一问一答，但输出全部标成 `[S1]`：

```
## 00:00:00 ~ 00:00:24  [S1]
What happened since we last did a podcast? Yeah, it's a small stuff. ...
```

原因：快速交替的话句很短，聚出的簇时长占比低 → 被当作碎簇合并掉了。
**5% 这个阈值是在"总人数正确"和"快速轮次保留"之间的取舍。**

缓解办法：

- 已知人数时用 `--num-speakers N`，不做碎簇合并，效果更好
- 调低 `min_duration_off`（当前 0.5 秒）可以让交替更细，但会增加碎段

### 6.2 不给出真实姓名

只回答"哪段是谁"。`S1`/`S2` 是聚类编号，跨视频不保证一致。

### 6.3 分离会让总耗时翻倍

180 秒音频分离约 30 秒，转写约 40~80 秒。所以默认关闭。

## 七、下一步建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| **1** | 用 `--num-speakers` 引导，或做基于轮廓系数的自动选 k | 自动判断人数是当前最大短板 |
| 2 | 自适应混排细分（只对混排块用 15 秒重跑） | 语言切换点更准，代价只落在问题块 |
| — | ~~降噪~~ | **不做**，实测无收益（见第四节） |
| — | ~~人声/伴奏分离~~ | 不做，背景噪声不影响识别；"唱歌变文字"需单独验证 |
